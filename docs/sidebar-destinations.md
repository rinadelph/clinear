## Current Upcoming

Linear team Current/Upcoming are cycle routes, not generic issue statuses: observed `/team/CLO/cycle/active` rendered actual Cycle 20 issues and `/cycle/upcoming` actual Cycle 21 planning. Hoja now shows nested Current and Upcoming under each team’s Cycles button (`frontend/src/main.tsx` sidebar line 60) and routes `/workspace/team/<key>/cycle/active|upcoming` via `routeView` and `TeamCyclePage`. The page queries the existing authenticated `cycles(filter:{team:{id:{eq:...}},isActive|isNext:{eq:true}})` contract, rather than deriving a cycle from dates or labels. If one exists it queries its issues filtered by both team and cycle ID; otherwise it explicitly shows No current/upcoming cycle. The selected sidebar child gets `aria-current=page`, and repeated route clicks remain scoped. Original Engineering currently has no active/next cycle: t1 direct URLs displayed those honest empty states. Unknown team key displayed Team not found instead of another team’s data. At 390px labels remain visible without document overflow; network error and 100+ cycle issues show an alert rather than a false complete count. No cycle was created and Linear stayed read-only.


## Teams

Linear team Home/Issues/Cycles/Projects/Views are team-keyed routes, unlike the previous Hoja Cycles/Projects/Views shortcuts to workspace pages. `routeView` and the sidebar now send each team’s key to `/workspace/team/<key>/home|active|cycles|projects/all|views/issues` (`frontend/src/main.tsx` lines 20–24, 60). TeamHome now resolves the matching team rather than `teams[0]`; unknown keys show Team not found. New `TeamIssuesPage`, `TeamCyclesPage`, `TeamProjectsPage`, `TeamViewsPage` query or filter real current-workspace data and show loading/empty/errors without using another team's rows. Issues and Cycles use authenticated team-id GraphQL filters. Team Projects currently checks the first 100 organization projects and filters their linked team IDs; if more exist, it warns about incompleteness rather than claiming an exhaustive list. Team Views shows team-filtered issue work while explicitly stating shared team view definitions are unavailable; it does **not** mislabel workspace saved views as team-owned. Each nested entry exposes `aria-current=page` when selected. At original t1 Engineering Home rendered real Engineering, Issues showed ten team rows, Cycles empty, Projects one Hoja dogfood row (click opened the matching project detail), Views showed ten filtered issues and the unsupported-sharing notice. Unknown team Home and Projects showed an alert. No second authorized team exists in this workspace, so multi-team isolation beyond source filters remains browser-unverified.


## More

Linear Workspace More opens a searchable menu with Members, Customers, Teams, Customize sidebar. Hoja has a real Members page (`frontend/src/main.tsx` MembersPage and `view==='Members'`), so Workspace More now toggles a focused menu with Members and a plain text notice that Customers/team administration/sidebar customization lack backing contracts (`main.tsx` sidebar). It does not fabricate inert menu links. Repeated button activation toggles the menu; Escape dismisses; selecting Members closes and routes `/workspace/members` with the actual member UI. At t1 the menu expanded, Escape closed it, and the Members item navigated to the page. The existing global More Board/Cycles/Members/Settings remains as legacy navigation rather than removing working links. Linear Join a team/favorite folder/fully customizable sidebar still have no supported local mutation or configuration, and were not imitated. Narrow popover width is bounded to viewport. Outside-click dismissal/focus restoration beyond native buttons remains unverified and is not claimed.

## Result

The missing Current/Upcoming cycle links now lead to data-backed team-filtered cycle states, with correct selection and honest empty pages. Team Home/Issues/Cycles/Projects/Views now use team-keyed routes instead of hardcoded first-team or workspace-wide destinations. Workspace More exposes the supported Members action and states why Customers/Teams admin/Customize sidebar are not available. Version is 0.20.0 (`VERSION`, `pyproject.toml`, `CHANGELOG.md`). These changes are **not 1:1 Linear parity**: there is no local cycle data in the original workspace, shared team views, customer records, Join a team/folder/custom-sidebar workflows, or proof of cross-team behavior from a two-team browser fixture. Existing global More links remain; no data was mutated in either the original or external account. Dirty work was preserved; no commit/tag/release.
