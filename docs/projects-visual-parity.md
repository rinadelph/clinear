## Comparison

The user's visual complaint is confirmed. Linear loads **Inter Variable** (`document.fonts`: weight 100–900, loaded; network `static.linear.app/fonts/InterVariable.woff2?v=4.1`), while Hoja merely names `Inter` in root CSS but has **zero loaded font faces** and no font asset in its frontend: Chromium falls back to installed system sans. At the same desktop viewport Linear Projects heading is 13px/500, bounding width 50.7px, x263/y22.5; Hoja heading is 14px/600, width 63.3px, x270/y20.2. Linear main x244–1256, Hoja x252–1256 (8px shift from sidebar). Linear first list row y128, height48; Hoja first row y178, height52. Linear table begins immediately after the 44px tab strip, with compact right-aligned filter/display controls; Hoja adds a separate 44px toolbar, an invented `1 of 1 project` count, and more/bolder text. Linear column captions include Name, Health, Priority, Lead, Target date, Issues, Status; Hoja instead shows Name, Health, Lead, Target date, Status, Progress. Values differ because account data differs; a cosmetic change must not invent priority, issue totals, health or history.

Linear project overview puts its real 24px/600 name at x303/y208 and 15px/450 summary below, with a compact properties sidebar and description below resources/update. Hoja draws a 30px/700 name at y145, repeats description as a summary, and places a giant always-open Edit project form from y257 across the full width, pushing updates and issues far below the fold. The app has no separate summary column: local project description can be shown, but cannot be identified as an independently persisted Linear summary. A 390px narrow comparison and post-change capture remain to be done.

## Source map

`frontend/index.html` has no font loading. `frontend/src/styles.css` line 1 names Inter but defines no `@font-face`; font and visual rules are concatenated on lines 1, 6, 43–69 and 389–405. `frontend/src/main.tsx` lines 195–212 own Projects list text/table/toolbar; lines 213–215 own detail header, editor, publisher and related sections. `cliniar_server/schema.graphql` Project fields contain `description`, not a separate summary or priority. Font substitution should use a distributable open Inter asset packaged locally, not a fetched Linear-owned resource; preserve fallback. The shell `/workspace` sidebar is shared by other routes, so avoid changing global typography unless its consumers are checked.

## Scope

Correct the measured font loading, title/row/sidebar typography, List header/text/column hierarchy, and project overview's oversized edit form versus Linear. Keep distinct actual data and supported actions, never show mock priority or imported descriptions. Other Linear-specific properties and assets remain separate product gaps (`docs/projects-parity.md#Result`).

## Implementation

Added the OFL-licensed `@fontsource-variable/inter@5.3.0` dependency (`frontend/package.json`, package lock) and loaded its `wght.css` from `frontend/src/main.tsx` line 1. `frontend/src/styles.css` Projects rules after line 406 select the self-hosted `Inter Variable` with a local/system fallback rather than depending on Linear's private CDN; no global font change is imposed on other routes. Replaced the list's invented count, extra toolbar row, oversized name/icon and stale Health/Progress headers with observed compact List hierarchy and backed values: Name, Health glyph, Lead, Target date, Issues placeholder when not yet queried, Status progress. The placeholder **—** explicitly means this list does not know issue counts and must not be read as zero; the existing detail query supplies actual issue rows. Linear's Priority column is withheld because `Project` has no priority field. Side-effect-free display/filter buttons remain in the tab strip. The list row's project identity, click destination, filtering and pagination still use the same data and handlers (`main.tsx` ProjectsPage).

On detail, `ProjectDetails` keeps an explicit Edit project button and collapses its previously dominant form by default. The observed compact name/summary scale, data-backed Status/Lead/Dates/Teams properties, a small update-entry button linking to the existing Activity composer, and readable description appear above the existing progress/issue sections. No summary column was introduced; the description preview and full description are the same persisted field, not independent values. At narrow width the properties panel appears first (as observed), followed by actual project text; no fake Priority/Members/Slack/Resources or Linear-only update history was rendered. The same Save/Discard/archive handlers stay in the editor and project updates continue to be submitted only on Activity. CSS scopes font/geometry to Projects rather than mutating shared styling (`styles.css` Projects rules after line 389).

Limitations: Linear's exact font binary is not copied; the open Inter Variable version is a close distributable substitute. Distinct account content, sidebar hierarchy, populated-list counts, property integrations and historical activity remain different; pixel parity has not been established. The narrow properties panel has fewer fields because Hoja has fewer backed properties.

## Result

The font discrepancy was real: Hoja previously named Inter without loading it. Projects now self-hosts an Inter Variable font and uses the measured 13px/500 header, 48px list rows, a compact table toolbar and a less dominant detail editor, versioned as 0.18.1 (`VERSION`, `pyproject.toml`, `CHANGELOG.md`). Comparable headed-browser screenshots support substantial typography and geometry improvement, **not 1:1 visual parity**. Hoja still has different project data, unsupported Priority/health/history/integrations, a different sidebar and a simpler overview hierarchy. Those gaps are explicitly visible rather than disguised; no data was invented and external Linear remained unchanged.
