## Controls

The existing status/priority/team/project/cycle/content filters combine conjunctively; one Clear action resets all of them. Display now supports Focus, Status, Project, Priority, Cycle, Label and Team grouping (`frontend/src/main.tsx` lines 77–94) (each loaded issue belongs to one group; Label uses its first label for deterministic non-duplicating counts). Project, Created date, Assignee, Priority, Status, Labels and Due date columns can be toggled independently and persist in the browser profile. The date range uses a visible `YYYY-MM-DD` input; missing dates do not match bounded dates. This is client-side filtering on loaded pages, not a server-wide total: the count explicitly says “loaded issues (more available)” while PageInfo has another page. Unsupported Linear-only agent/customer/revenue, blocking graph, sub-grouping and disabled Board/view ordering are not advertised as working controls. With absent fields the filter yields no match rather than fabricated metadata; failed GraphQL page requests retain existing rows with an error/retry control.

## Pagination

returns `hasNextPage` and an opaque cursor, and rejects malformed cursors.
Hoja requests first 100 plus PageInfo, exposes Load more only when more results
exist, guards duplicate clicks and non-advancing cursors, deduplicates IDs,
and provides error/retry. On workspace switch, cursor and page state reset.

## Result

This pass added supported relationship/date filters, configurable metadata columns and additional grouping, and made incomplete loaded-page counts explicit. It also fixed stale-session handling after an observed 401. Exact Linear focus blocking groups, cloud-only filters/columns, historical pre-migration events, and the unobserved details-pane behavior remain unimplemented; these are not claimed as 1:1. All original browser tabs remain open, with the disposable test tab retained; because its `127.0.0.1` cookie shares a host with original Hoja, only one of those two server sessions can be authenticated at a time in this browser profile.


Implemented cursor-based issue pagination and a load-more UI, expanded supported filters/display controls, and added a forward-only audit event feed with cursor pagination. These are **not full Linear parity**: the old database has no recoverable event history, some Linear filter/display dimensions are absent from Hoja, and the one-issue original tenant cannot demonstrate later pages without adding data. The disposable authenticated API **and headed browser** E2E demonstrate later pages; the original one-issue tenant cannot show that state. Original Hoja and Linear tabs were preserved; a disposable test account and third tab were added. The original tenant schema was migrated, and its server session was restarted with new code.
