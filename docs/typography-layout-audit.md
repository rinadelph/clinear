## Baseline

Existing headed Chromium tabs: t1 authenticated original Hoja `http://127.0.0.1:8790`, t2 authenticated read-only Linear, t4/t5/t6 local fixtures. At 1264×900, Linear `/cloverve/initiatives/active` was an empty reference; Hoja `/workspace/initiatives/active` was also empty. Hoja representative routes inspected: My issues, Pulse, Inbox, workspace Views, Projects, Initiatives, team Home/Board, Cycles, Members, Settings, Agent. At 390×844 Hoja Initiatives had no document horizontal overflow. Project is substantially dirty, including existing untracked frontend and prior screen work. No data will be altered on Linear or the original Hoja workspace in this styling pass.

## Comparison

Linear uses a loaded Inter Variable font. On the empty Initiatives view its heading is 13px/500 at x263/y22.5. Hoja Initiatives names uninstalled `Inter` and falls back to system sans, with heading 13px/600 at x270/y20.9. Comparable Linear Pulse and My issues headings also measured 13px/500 at x263. Hoja My issues, Pulse and Inbox all render 13px/600 with the same unloaded Inter declaration. Hoja Projects and workspace Views already self-host Inter Variable and measure 13px/500 after the earlier focused fixes. Team Home, Cycles, Members, Settings and Agent instead use generic 27–30px/700 headings; these are different screen templates and must not be blindly forced into compact 13px screen headers without their own reference comparison. Initiatives empty reference has no populated rows, so populated Initiative typography cannot be claimed pixel-equivalent. Empty/list controls, responsive content, focus, and mobile navigation must remain usable.

## Shared

`@fontsource-variable/inter/wght.css` already bundled the local woff2 from `frontend/src/main.tsx` line 1. `frontend/src/styles.css` after the earlier screen-specific rules now defines `--hoja-font-ui`, compact 13px/500 header role, 12px body role, 1.5 line-height and 28px compact control height, using a system-font fallback. It applies the font to Initiatives, Pulse, Inbox, workspace Views, Projects, project detail and My issues list; the My issues header/tabs are siblings of its list and therefore explicitly inherit the same font via `.main:has(.my-issues-view)`. A higher-specificity legacy title rule required scoped overrides to actually achieve 500 weight. The shared role changes font/weight, not semantic headings, API data, navigation or unrelated 27–30px team/settings templates. Focus-visible outlines remain and long labels wrap or ellipsize within their existing screen-specific layout. Dark theme keeps existing color tokens; font face is theme-neutral. `font-display:swap` from the npm font package preserves system fallback when unavailable; 390px and zoom checks are in Verification.

Team Home, Cycles, Members, Settings and Agent retain larger template-specific headings because no matching authenticated reference was established. The existing Initiative view does not render any project row in the original workspace, so row typography was checked through source constraints, not a populated reference pair. Long titles wrap in existing `.initiative-row` width rules; missing project/date values keep their placeholders. Shared focus outlines and responsive scroll behavior remain scoped rather than flattening every screen into one template.

## Result

This pass fixed a real site-wide design inconsistency rather than repeating a page-specific override: compact work surfaces across Initiatives, Pulse, Inbox, My issues, Projects and workspace Views now share the self-hosted Inter Variable/13px/500 header role, consistent font fallback/focus, and compatible narrow navigation. Initiative empty/list/control typography was aligned without altering routes or backend data. The version is 0.19.1 (`VERSION`, `pyproject.toml`, `CHANGELOG.md`). **Remaining:** populated Linear Initiatives were unavailable, Hoja's empty illustration/sidebar and My issues container still differ from Linear, team Home/Cycles/Members/Settings/Agent use distinct larger templates pending their own visual comparison, and screen-specific feeds retain different layouts intentionally. No pixel-perfect parity claim, no unit tests, no commit/tag/release. Dirty work and browser tabs were preserved; Linear remained read-only.
