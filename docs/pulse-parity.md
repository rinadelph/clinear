## Source map

`cliniar_server/schema.graphql` presently exposes projects and project mutations, but no project update post query/type. Project `description` is metadata, not a dated update; `myIssueActivity` is issue mutation history, not Pulse. Add a real org-scoped project-update read path and show honest empty state where no posts exist. No Linear posts should be copied into Hoja. Reaction, comments on project updates, subscription scheduling, custom view creation, and Popular/For me ranking cannot be claimed from existing server data; keep controls read-only or explicitly unavailable. Preserve wire-facing Linear GraphQL naming.

## Data

The new revision-9 `project_update` table is organization/project scoped and stores body, timestamp, actor, health/status and progress snapshot (`cliniar_server/db.py` lines 317–328, 505). GraphQL `projectUpdates(first,after,filter)` and `ProjectUpdate` are in `schema.graphql` lines 56,185–196,244; `store.py` lines 770–795 orders by timestamp/ID descending with an active-project, project-organization join and optional project filter; `resolvers.py` lines 105–119,206–222,440–449 handle cursor and nested project/actor. No records are fabricated from project descriptions or issue events. The frontend `PulsePage` in `frontend/src/main.tsx` lines 72–101 fetches only on mount, uses the server's pageInfo for Load more and deduplicates IDs, checks cursor advancement, resets data across workspace key remount, and ignores stale responses on unmount. Honest empty, loading, error/retry states are rendered. For me/Popular labels currently show the same chronological set with an explicit visible notice (and tooltip) disclosure; following graph, ranking, email subscription, post reactions/comments and custom views require unsupported server data and remain unavailable. No live post was submitted.
