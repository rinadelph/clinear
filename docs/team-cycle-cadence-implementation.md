# Approved cadence implementation evidence

## Contract

Approved policy is `docs/team-cycle-cadence-plan.md#Decisions`: opt-in only, admin-selected weekday, fixed 1-week/no-cooldown/two-upcoming, local team timezone, short initial current interval, 00:01 local weekday boundaries, half-open UTC intervals, bounded read reconciliation, no automatic issue rollover, legacy-cycle rejection, no disable/reanchor in phase one. Migration and lifecycle sequence are at `docs/team-cycle-cadence-plan.md#Implementation plan`.

Current source map: `cliniar_server/db.py#L163-L182` team timezone/active pointer, `#L373-L390` cycle number/start/end/unique team-number, migration map `#L527-L542`; `store.py#L655-L682,#L1078-L1124` reads and active/next selection; `writer.py` has transactional writes but no cycle lifecycle; `resolvers.py#L57-L64,#L214-L230,#L325-L334,#L379-L392,#L573-L582` authenticated context, team/cycle reads, admin pattern. `schema.graphql#L65-L68,#L84-L102,#L138-L187` GraphQL boundary; `frontend/src/main.tsx#L20-L35,#L44-L69,#L230-L243` sidebar and team pages. SQLite `make_engine` enables WAL and foreign keys; PostgreSQL uses pool pre-ping (`db.py#L463-L480`). Cross-process SQLite write locks and PostgreSQL row locks need explicit dialect handling. Disabled legacy teams must preserve their existing `active_cycle_id` and cycles; only an admin enabling a cycle-free team creates rows. Local IANA times can be nonexistent/ambiguous even at 00:01, so the calculator must detect rather than assume. The plan's `start today` policy requires an exact first-interval instant; use team-local day's 00:01 only if not in the future, otherwise start at the selected upcoming 00:01, avoiding a retroactive current cycle before its start.

## Scheduler

Revision 12 adds opt-in team fields and cycle cadence boundary uniqueness (`cliniar_server/db.py` rev12); `cliniar_server/cadence.py` calculates strict 00:01 team-local boundaries, rejecting IANA/DST gaps/folds, and reconciles fixed one-week intervals in a caller-held transaction. `Writer.enable_team_cadence` guards weekday, legacy cycles, team org/archived state and unsupported reanchor; `Writer.reconcile_team_cadence` uses SQLite `BEGIN IMMEDIATE` or PostgreSQL `FOR UPDATE` to serialize the team claim. Both return Current (or none before first boundary) and exactly two Upcoming; elapsed cycles receive completed_at at their stored end without modifying issue associations. Idempotency is constrained by team+boundary and team+number. Ad hoc isolated SQLite verification (no test file) observed three rows after enable; repeated reconciliation retained Current ID and count; 00:00 before a Tuesday boundary displayed no Current/two Upcoming, at 00:01 displayed Current/two Upcoming; later transitions advanced cycle number with next horizon. A backwards clock read retained existing future rows without deleting them. Catch-up beyond a bounded interval count raises an explicit error before commit. DST and concurrent workers need further isolated checks; no claims beyond those observations.


## API

`cliniar_server/schema.graphql` now exposes `teamCycleCadence(teamId)` and admin-only `teamCycleCadenceEnable(teamId,weekday)` returning enabled/weekday/timezone/policyVersion/activeCycle/two Upcoming fields. `resolvers.py` reads authenticated org/user, checks `store.get_user(...).admin` on mutation, calls Writer's transactional enable; the read reconciles only the addressed team. Team cycles/activeCycle and team-filtered cycles reads call reconciliation to avoid stale sidebar state. Existing disabled/legacy teams retain prior read behavior. An ad hoc isolated GraphQL execution (not a test file) confirmed disabled query returned no cycles, enable produced numbered 1 + 2/3, repeated query and mutation retained IDs. A separate isolated execution confirmed non-admin mutation denied, missing team and invalid weekday errored, with zero cycle rows and enabled false afterward. Stale HTTP response/forced DB write rollback and PostgreSQL role behavior remain unverified.


## UI

`frontend/src/main.tsx` now routes `/workspace/team/<key>/cycles/settings` ahead of generic Cycles and renders `TeamCycleSettings` from the selected team ID, not a global default. The team Cycles screen offers Cycle settings; settings query returns saved enabled/weekday/timezone/current/upcoming. A required weekday select starts blank; submit is disabled until selected and while pending. An authorized success renders only authoritative returned cycle IDs/names, keeps fixed one-week/no-cooldown/two-upcoming limits explicit, and discloses unavailable issue auto-assignment/rollover and edit/disable. Errors retain the draft and warn to reload/reconcile before retrying an uncertain mutation. Cancel/back does not submit; narrow styling and native focus are in `frontend/src/styles.css`. The existing viewer query now requests `admin`; non-admin sees a read-only permission notice and disabled submit, while the API still enforces authorization. This role-aware state and multi-team browser behavior remain to be verified.
