# Sidebar flow follow-through

## Baseline

Read-only inspection of the existing headed browser: t1 authenticated original Hoja `127.0.0.1:8790`, t2 authenticated Linear `/cloverve/team/CLO/views/issues`, local fixture tabs t4/t5/t6 preserved. Current source remains substantially dirty/untracked, notably `frontend/src/main.tsx` and `cliniar_server/*`; AGENTS.md requires version/changelog and no hardcoded organization defaults. ## Contracts

Team cycle sidebar Current/Upcoming route → `cycles(filter:{team.id,isActive|isNext})` → selected ID → `issues(filter:{team.id,cycle.id})`. The actual backend `r_cycles` returns `_conn(store.cycles(... )[:first])`: it ignores `after`, supplies `hasNextPage=false`, and cannot prove a 100-cycle list is exhaustive. `issues` has a real cursor. Previous TeamCyclePage displayed a warned first 100 issues; CycleDetail instead counted/linked **all first-page team issues** regardless of cycle and the team Cycles list likewise counted all team issues. Selecting a cycle navigated `/workspace/cycle/<id>`, but direct reload did not fetch that ID. Team Home's View board/View cycles buttons navigated generic workspace routes and loaded-page counts were not labeled. These are feasible defects with current GraphQL filters.

Team Projects route requested `projects(first:100,filter:{})` then filtered returned team associations in browser, even though projects connection has real cursor now. It could omit matching projects past the first page. ProjectFilter had no team comparator; team-scoped backend filtering is feasible through the existing project_team relation and organization checks. Team Views is a team-filtered issue feed presented under a Views heading while explicitly saying shared team views unavailable; browser-local workspace Views exist but are not team-owned. No server-backed custom-view schema exists. Workspace More menu offers backed Members and text for unsupported Customers/Teams admin/sidebar customization, but only Escape dismisses, not outside click; focus restoration and menu keyboard traversal were not verified. Agent is a nonfunctional unconfigured-service notice, not a working action. These are separate from the observable menu link contract.

## Scope

Fix verifiable cycle ID filtering/detail reload and team navigation, team projects pagination/scoping, and local menu dismissal/focus where appropriate. Do not invent cycle creation, shared team views, customer/agent integration, or automatic organization-wide permissions. If a backend view model is necessary for shared views, treat it as a separate product feature. No unit tests per user preference; verify via isolated browser fixtures and targeted GraphQL calls where real local data is absent.

## Team cycles

Team Home action buttons now navigate team-keyed Issues/Cycles/Projects routes instead of generic workspace screens (`frontend/src/main.tsx` TeamHome). Global CyclesPage counts only loaded issues whose `cycle.id` matches each displayed cycle, and labels counts as loaded rather than falsely counting all team issues. `CycleDetail` has been replaced with an authenticated `issues(filter:{cycle.id})` query, explicit loading/empty/error and honest 100+ warning; route `/workspace/cycle/:id` now fetches a single `cycle(id)` by ID so direct reload cannot show stale or all-team data. Backend GraphQL `cycle(id)` now resolves only the current organization; a missing ID yields null. The original server was restarted to load it. t1 Team Home View team cycles reached `/workspace/team/eng/cycles`; current original database has zero cycles, so populated issue membership needs an isolated fixture. Before backend restart, direct `/workspace/cycle/missing` exposed the absent-field validation error; after restart it showed **Cycle not found in this workspace**, confirming the contract is live. Team Home View team cycles routed to `/workspace/team/eng/cycles` rather than the workspace list.


## Projects Views

The first implementation filtered `projects(first:100)` in the browser, so a later-page team project could disappear. `ProjectFilter.team:TeamFilter` now applies an organization-resolved `project_team` association constraint in `cliniar_server/schema.graphql`, `store.py` and `resolvers.py`, preserving the existing created-at/ID project cursor. `TeamProjectsPage` requests only projects linked to the current team with `first:50,after`, dedupes stable IDs, guards nonadvancing cursors and exposes Load more, loading/error/retry and empty states. The original Engineering team showed its single real dogfood project after the backend restart; no cross-team item was displayed. Team Views now supports per-team browser-local saved filters in `hoja_team_views_<teamId>`, showing only issues fetched for that team; it clearly says shared views are unavailable. In t1 a local Engineering view filtered ENG-2 to one row, survived reload as a named entry, and reselecting it restored the filter. This is local persistence, not server collaboration. Full project-filter pagination and independent two-team browser proof remain unverified.


## More

Workspace More still offers only backed Members, with an explicit text blocker for Customers/Teams administration/Customize sidebar. A scoped pointerdown listener now dismisses the menu on outside activation; its button/menu references are inside App only, avoiding leaks to ProjectDetails. Existing Escape dismissal and repeat toggle remain. At t1 on team Views, More opened, clicking the main heading dismissed it, and reopening/Escape dismissed it again without navigation. Agent still shows an unconfigured service notice; it is not promoted to a working menu action. Missing permission handling comes from the existing authenticated Members resolver, not a fabricated admin option. Focus restoration after dismissal and full keyboard menu traversal were not proven and remain gaps.
