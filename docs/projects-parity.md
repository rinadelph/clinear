## Inventory

Populated List has sortable Name/Health/Priority/Target date/Status, checkbox selection, inline icon/health/priority/lead/date/issue-count/progress controls and navigable project rows. Display options exposes List/Board/Timeline, grouping (none, initiative, lead, member, status, priority, label, lead team, team, health, start/target date), ordering, closed-project visibility, and toggles for ID, Milestones, Summary, Priority, Status, Health, Teams, Lead, Members, Dependencies, Start/Target date, Issues, Created/Updated/Completed, Customers, Customer revenue and Labels. Board showed status columns including empty Planned and cards; Add filter offered AI/advanced and many concrete attributes. No filter was applied to the external account. External New project opens a draft form with project name, summary, description, status, priority, lead, members, start/target dates, labels, dependencies and milestones; Discard returned without creating.

An existing Linear project exposes Overview, Activity, Issues and Add new view. Overview has inline name/summary/description, properties sidebar (state/priority/lead/members/dates/team/labels), resources, customers, project updates, milestones, dependencies, progress and activity; actions include favorite, URL copy, notifications and a menu of Copy/Favorite/Subscribe/Remind me/update schedule/Slack/description history/show activity/Delete. Issues groups by state and has new issue/filter/display. Activity exposes Comment/Update tabs and a timeline. These are observed controls, not proof of their post-submit behavior. Linear was not mutated. At 390px its project overview did not horizontally overflow.

Hoja currently shows a searchable card grid, state and team selectors, count, New project, then a single detail page with explicitly saved name/description/state, archive confirmation, a project-update publisher, stats and linked issue rows. There is no local equivalent of the observed List/Board/Timeline display menu, separate Overview/Activity/Issues tabs, or broad properties panel. Its local team issue stages are not project-owned statuses. Missing account-specific data (customers, Slack, AI, history) cannot be fabricated.

## Scope

Feasible local work starts with replacing the card-only project list with observed List/Board controls backed by real fields, then presenting project detail as Overview/Activity/Issues and reconciling local editor, publisher and navigation. Backing capabilities must be verified before displaying mutable controls. Customer, external Slack, AI, historical activity and unobserved submission outcomes remain out of parity scope unless real data/contracts can be established. Empty/error/mobile and persisted flows require separate local verification. New independent screens may be split from the current task graph after deeper inspection.

## Verification

Authenticated t2 Linear Projects `/cloverve/projects/all` was read-only: populated List, Board, Timeline, display grouping/ordering/property toggles, filter inventory, create draft/discard; one project `/overview`, `/activity`, `/issues` exposed detailed controls at 1264×1258; overview at 390×844 had no document overflow. No external changes or post-submit behaviors were asserted.

After the final client reconciliation, Issues renders only project-filtered query rows rather than temporarily falling back to the generic first-page workspace issues; successful publication on the Activity tab triggers a refresh of that feed. The former was browser-checked on t1 with nine rows; the latter was not submitted again to avoid duplicate project updates.

At original t1 `http://127.0.0.1:8790/workspace/projects`, List showed the single dogfood project, status Board showed one In Progress and zero other status columns; filter search no-match and Clear restored the row. Display Timeline honestly explained unavailable support. The detail `/workspace/project/<id>/issues` showed nine actual project-scoped rows (GraphQL 200) and ENG-2 search narrowed to one, row navigated to issue detail and browser back returned. `/activity` showed one real scoped update (the backend initially rejected `ProjectFilter.id`; after adding field and restarting original `hoja-web`, it recovered). A missing project ID showed Project not found without stale detail. Direct Issues reload showed nine, and browser back across Activity/Issues restored tab selection. At 390px the original list/board and detail did not overflow the document; the table scrolls in its own container. No browser errors/console entries were observed on original t1; sampled GraphQL returned HTTP 200 and both exact Projects and detail paths served HTML 200 with `/ready` ready.

Isolated t6 `http://localhost:8803/workspace/projects` began empty, created a local-only started project via name/status and Enter, showed one row, persisted reload, saved description via Enter and persisted reload, then Discard restored its last saved value. Empty name left Create disabled. The isolated fixture service initially held the old `ProjectFilter.id` schema; it was restarted without changing fixture data, after which `/activity` showed **No project updates yet** with no alert. No unit tests were added or run. Forced failure, permission role variation, 100+ project/50+ issue pagination in browser, long data and external mutation outcomes remain unverified.


## Result

Hoja Projects now has genuine org-scoped cursor pagination, a populated List/status Board with supported filters and display controls, Overview/Activity/Issues detail navigation, scoped update history, complete project-filtered issue pagination, and a richer local create draft. Missing/archived project details are hidden; version 0.18.0 is in `VERSION`, `pyproject.toml` and `CHANGELOG.md`. Browser evidence covers the original one-project/nine-issue/one-update workspace, an isolated create/edit fixture, narrow layouts and direct/return routes. Frontend build, Python compilation, GraphQL schema construction and `git diff --check` passed. Existing unrelated dirty files remain intact; no unit tests were created or run, and no commit, tag or release was made.

This is **not every screen/button/flow 1:1**. External Linear has a populated Timeline, inline priority/health/lead/date controls, manual sorting, selection/bulk operations, initiative and other grouping, advanced/AI filters, view creation, resources, customers, subscription/notification and Slack integrations, milestones, dependencies, comments, history, true separate summary, a richer properties sidebar and project-specific stages. Hoja exposes only backed functionality or explicit limits, and its UI has not been pixel-diffed against Linear. Linear mutations remained read-only; inaccessible states and unsupported integrations cannot be claimed as verified parity. Further independent features require a scoped data model, authorization/permissions, and browser checks rather than cosmetic buttons.
