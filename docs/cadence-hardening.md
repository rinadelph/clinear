# Cadence authorization and read-state hardening

## Baseline

A new disposable SQLite database `/tmp/hoja-cadence-hardening/hardening.db` was migrated to revision 12 with two distinct organizations, users, memberships and teams. Only this `/tmp` DB will receive cadence writes; original Hoja `~/.local/share/cliniar/hoja.db` and the existing headed browser tabs t1/t2/t4–t8 remain untouched. No open mode or unverified shared login is used; the API can be exercised with each fixture's bearer identity without emitting tokens. The worktree is already substantially dirty/untracked; AGENTS.md requires a version/changelog bump only for an actual product code change. No unit tests will be added/run.

## Contracts

`cliniar_server/app.py#L47-L95` extracts session or bearer token and supplies `(user_id, org_id)` to GraphQL context. `store.py#L64-L85` resolves active API keys joined to active users; `store.py#L89-L107` creates browser sessions for resolved token identities, while `#L383-L390` reads active membership for session context. `app.py#L37-L45` calls `resolve_token_identity` for open mode, which requires an unambiguous SQLite organization/user (`db.py#L750-L786`); a two-org fixture disables open mode by ambiguity. Legacy identity membership backfill `db.py#L510-L526` creates distinct identities for legacy profiles. `resolvers.py#L57-L60,#L325-L351,#L395-L411` sends authenticated organization to cadence Writer; `writer.py#L154-L200` selects by org+team and checks admin for mutation in resolver. `cadence.py#L89-L185` writes cycle rows constrained to org+team in a transaction. `frontend/src/main.tsx` TeamCycleSettings around line 236 loads cadence by team ID and uses a `live` effect guard on unmount/team-ID change; TeamCyclePage uses route state and writer-backed cycle reads. A read intentionally materializes due cycles, but a failed transaction must not leave a partial state; a stale late response must not overwrite a newly selected team's data.

## Authorization

Disposable two-organization GraphQL fixture: Org A team CAA enabled with three cycles; Org B team CBB disabled with zero. Authenticated context A querying its team returned enabled true, active ID and two Upcoming, matching `team.activeCycle` and team-filtered cycle list (3). Context B querying its own team returned enabled false/none and list 0. A querying B's direct team ID, or B querying A's ID, returned `Team not found in this workspace` from `teamCycleCadence`, preventing other fields in that combined GraphQL request from returning data; direct `team(id)`, `cycle(id)` and filtered `cycles` were also checked in a separate adversarial request: foreign `team` and `cycle` returned null, foreign filtered list returned no rows, while the cadence error remained. B's attempt to enable A's ID failed; persisted counts stayed A=3, B=0. Deactivating B's fixture membership made `Store.membership_for_profile` return None. **Correction:** an initial source reading suggested `app.py` would accept a stale session, but `Store.resolve_browser_session` (`store.py#L251-L269`) itself checks active membership and returns None. Thus the supposed revocation defect was a false inference. A disposable Store session probe confirmed a valid session resolved before membership deactivation and returned None afterward; no auth code repair is justified. Open-mode identity resolution in this two-org DB raised ValueError rather than choosing a first org. The initial ad hoc query shape had a GraphQL syntax error and returned no evidence; it was corrected before interpreting the access matrix. Token values were never printed; no original DB was touched.


## Read rollback

**Failed authenticated read:** Disposable `/tmp/hoja-cadence-hardening/failed-read-actual.db` enabled cadence with an injected clock 16 days before current wall time, so a real `teamCycleCadence` GraphQL read had to materialize due cycles. A disposable SQLite trigger aborted its next cycle insert. GraphQL returned an error and `data:null`; a fresh DB connection found the same cycle count and active pointer as before (transaction rollback). After dropping the trigger, a fresh GraphQL retry succeeded, advancing to Current cycle 3 and five total rows. A first attempt to inject on a fixture already caught up generated no insert and thus no failure; it was discarded as non-evidence.

**Late/stale read:** The current `TeamCycleSettings` React effect has a `live` cleanup flag keyed by team ID, so an unmounted/changed-team query completion is intended to be discarded. This turn did not produce an independently controlled A/B delayed HTTP response in a browser profile; source reasoning is not a UI verification. The same-view `Team cycle` route has a route key and checks `location.pathname` before accepting a result. A controllable isolated browser interception or dedicated client harness is still needed to prove latest-request ownership, particularly when organization switches retain a component. Do not claim the stale UI sequence passed.


## Repair

No cadence authorization or transaction defect was demonstrated: own-org and adversarial direct-ID/filter queries respected organization scope, and a failed due read rolled back before any partial effect. An apparent inactive-membership defect was corrected after inspecting `Store.resolve_browser_session`, then the disposable session probe showed revocation works. No speculative product code change was made. A stale A/B browser response sequence remains unverified, so no client guard is claimed fixed. The next necessary action is an isolated delayed-response browser probe if this risk is prioritized.


## Result

Cross-organization cadence query, team/detail/filter and mutation probes with two fixture orgs showed no foreign data; open-mode ambiguity refused a default identity. A due read failed under an injected SQLite write error with `data:null`, zero partial effect and successful retry after removing the trigger. Browser-session membership revocation was checked and worked; the earlier defect hypothesis was false. **Not verified:** controlled late A/B client response and UI loading/error preservation, PostgreSQL concurrency and broader open-mode deployments. No product code changes or version bump were justified by this read-only probe. Original Hoja DB, dirty work, browser tabs and Linear remained untouched; no unit tests, commit or release.
